# display-image-inspection — 인수인계 브리핑

## 용도
스마트폰 디스플레이 검사 장비가 찍은 이미지에서 불량(얼룩·스크래치 등 배경과 밝기가 크게 다른 부분)의 위치를 찾는다. 이미지 10장을 한 번에 훑어 어느 이미지에 불량이 있는지, 화면 좌표 어디인지를 보고한다.

## 입출력
- 입력: `images/*.pgm` — PGM(P2, ASCII 그레이스케일) 형식 검사 이미지. 실제 검사 장비 출력 포맷이 다르면 `src/main.py`의 `load_pgm` 함수만 그 포맷에 맞게 바꾸면 된다.
- 출력: 콘솔에 이미지별 불량 유무·위치와 전체 평균 불량 크기(px)를 출력하고, `images/defect_report.csv`에 `file, has_defect, center_x, center_y, bbox_x, bbox_y, bbox_size` 열로 저장한다.
- 실행: `python samples/display-image-inspection/src/main.py` (이미지 폴더·출력 경로를 바꾸려면 `python samples/display-image-inspection/src/main.py <이미지폴더> <출력.csv>`)

## 수정 시 건드릴 파일
- `src/main.py` — `load_pgm`(이미지 읽기) → `estimate_background`(정상 밝기값 추정) → `find_defect_clusters`(배경과 크게 다른 픽셀을 flood-fill로 묶어 하나의 불량으로 판정) → 리포트 출력 순서로 구성되어 있다. 세 단계를 나눈 이유는 "이미지 포맷이 바뀌면 `load_pgm`만, 판정 기준이 바뀌면 `find_defect_clusters`만" 손대면 되도록 서로 다른 변경 이유를 분리해둔 것이므로, 수정 요청이 어느 쪽인지에 따라 건드릴 함수가 정확히 나뉜다.
  - `estimate_background`를 고칠 때 주의: 평균이 아니라 **중앙값**을 쓴 이유는 불량 픽셀이 전체 밝기 평균을 끌어당기지 않게 하기 위해서다. 단, 불량이 화면 절반 가까이를 차지하는 극단적 케이스에서는 오히려 불량 쪽을 "배경"으로 오판할 수 있다는 알려진 한계가 있다 — 대형 얼룩 검출 요구가 들어오면 이 로직부터 다시 봐야 한다.
  - `find_defect_clusters`를 고칠 때 주의: 4방향 flood-fill을 재귀가 아니라 명시적 스택으로 구현했다 — 이미지가 커지면 파이썬 재귀 한도(기본 1000)에 걸릴 수 있어서다. 스택 방식을 재귀로 되돌리면 큰 이미지에서 깨질 수 있다.
  - `load_pgm`을 고칠 때 주의: 현재 PGM 주석 줄(`#`)을 처리하지 않는다. 샘플 이미지엔 주석이 없어 문제가 없었을 뿐, 실제 장비 출력에 주석이 섞이면 파싱이 깨진다 — 포맷 교체 작업 시 이 부분을 반드시 확인해야 한다.
- `DEVIATION_THRESHOLD`, `MIN_CLUSTER_SIZE` (파일 상단 상수) — 이 알고리즘의 사실상 유일한 튜닝 지점이다. `MIN_CLUSTER_SIZE`는 픽셀 노이즈 한두 개가 우연히 임계값을 넘는 것을 진짜 불량과 구분하기 위한 값이므로, 오탐이 많으면 `DEVIATION_THRESHOLD`를 올리고 작은 불량을 놓치면 내린다.
- `images/*.pgm` — 샘플 검사 이미지. 실제 이미지로 교체 시 PGM(P2) 포맷 변환이 먼저 필요하다.
- 불량 평균 크기 통계(v2.0에서 추가)를 고칠 때: `main`의 기존 `report_rows` 순회 루프 안에서 `defect_sizes` 리스트에 값을 모아 마지막에 평균을 낸다. 별도 함수로 분리하지 않은 이유는 이미 순회 중인 루프에서 값을 얻을 수 있어 이미지를 다시 훑는 함수가 불필요했기 때문이다 — 통계 항목을 늘릴 때도 같은 루프 안에서 처리하는 것이 이 코드의 설계 의도에 맞는다.
