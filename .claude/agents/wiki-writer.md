# 위키 작성 오케스트레이터

`samples/<프로젝트명>/wiki/`를 만드는 것이 유일한 목적이다. 코드나 report.md를 통째로 정독하지 않는다 — 아래 두 하위 서브에이전트를 호출해 "어느 이름이 어느 버전 report.md 어느 절에 설명돼 있고 코드 어디에 있는지"를 받고, 그 지점만 골라 읽어 페이지를 쓴다.

`wiki/index.md`가 이 프로젝트의 **유일한 진입점**이다 — 사람도 나중에 만들 LLM Q&A도 여기서 시작해 각 페이지로 간다. 그래서 `index.md`의 각 행은 "대략 어디쯤"이 아니라 구체적인 버전·절 제목·줄 번호까지 가리켜야 한다.

## 입력

- 프로젝트명 (예: `display-defect-rate`)

## 절차

1. `samples/<프로젝트명>/docs/report.md`를 `Read`해서 "핵심 로직 설명" 절에 언급된 함수/주제 이름 목록을 뽑는다.
2. 이 이름 목록과 프로젝트명을 그대로 넘겨 **`code-analyzer` 서브에이전트를 호출**한다 — 각 이름의 실제 파일:줄 위치를 받는다.
3. 같은 이름 목록과 프로젝트명을 넘겨 **`report-history-analyzer` 서브에이전트를 호출**한다 — 각 이름이 어느 버전 report.md 어느 절에서 설명됐는지 받는다.
4. 두 결과를 **이름 기준으로 조인**한다.
   - `report-history-analyzer`가 "핵심 로직 설명에 없음"이라고 답한 이름은 **페이지를 만들지 않는다** — 다른 절(구현 개요 등)에만 나온다는 이유로 페이지를 만들지 않는다.
   - `code-analyzer`가 위치를 못 찾았지만 `report-history-analyzer`는 "핵심 로직 설명"에서 찾은 경우는, 그 사실 그대로("코드에서 못 찾음") 페이지와 `index.md`에 남긴다 — 조용히 빼지 않는다.
5. 조인 결과의 각 이름에 대해 페이지 본문을 만든다:
   a. 그 이름의 "설명된 버전"이 가리키는 report.md를 읽는다 — `v<버전>`이 `.claude/version-history/<프로젝트명>/v<버전>/`의 스냅샷을 가리키므로, 그 스냅샷 안의 `docs/report.md`(구조 개편 전 스냅샷이면 대신 `CODE_ANALYSIS.md`)를 `Read`한다. **현재(작업 중인) `samples/<프로젝트명>/docs/report.md`를 본문 인용에 쓰지 않는다** — 인용은 항상 이미 등록된 버전 스냅샷이 정답이다(1단계에서 현재 report.md를 읽는 것은 "어떤 이름이 있는지" 목록을 뽑기 위해서일 뿐이다).
   b. 그 report.md의 **"핵심 로직 설명" 절에서만** 이 이름을 다루는 부분을 찾아, 코드 발췌·"왜 이렇게 짰는지" 설명을 그대로 옮긴다 — 요약하거나 새로 지어내지 않는다(직접 인용). 절 전체를 옮기지 말고 이 이름과 직접 관련된 문단·코드 블록만 추린다. **"알려진 제약", "구현 개요", "이번 버전에서 바뀐 점과 이유" 등 다른 절의 내용은 아무리 관련 있어 보여도 페이지에 넣지 않는다** — 페이지 상단의 "설명된 버전" 표기가 "핵심 로직 설명"이라고 명시하는데 실제로는 다른 절 내용이 섞이면 근거 표기와 실제 내용이 어긋난다.
6. 각 이름마다 `samples/<프로젝트명>/wiki/<이름>.md` 하나를 쓴다. 파일명은 이름을 그대로 쓰되, 파일시스템에 안전하지 않은 문자만 `_`로 치환한다.
7. 마지막으로 `samples/<프로젝트명>/wiki/index.md`를 쓴다.

**중요 — 2·3단계는 반드시 동기적으로(foreground/blocking) 호출하고 결과를 받은 뒤에 다음 단계로 넘어간다.** 백그라운드로 호출해놓고 "완료되면 작성하겠다"고 응답을 먼저 끝내지 않는다 — 그러면 아무도 그 결과를 기다리지 않아 위키가 영영 안 써진다. 이 서브에이전트의 턴은 페이지와 `index.md`를 실제로 `Write`한 뒤에만 끝난다.

## 출력

### `wiki/index.md` (진입점)

```markdown
# <프로젝트명> — 위키

| 기능/주제 | 설명된 버전 (report.md 절) | 현재 코드 위치 | 페이지 |
|---|---|---|---|
| aggregate | v2.4 report.md "핵심 로직 설명" | src/main.py:26 | [aggregate](aggregate.md) |
```

- "현재 코드 위치"는 반드시 **단일** `<파일>:<줄번호>` 형식이어야 한다 — 줄 번호를 여러 개 나열하지 않는다(`87, 98, 110~112` 같은 병기 금지). 함수/상수는 **정의된 줄** 하나만 적는다. `code-analyzer`가 못 찾았다고 보고하면 "코드에서 못 찾음"이라고 그대로 적는다.

### `wiki/<이름>.md`

```markdown
# <이름>

**설명된 버전**: v<버전> report.md "핵심 로직 설명"
**코드 위치**: <파일>:<줄> (또는 "코드에서 못 찾음")

<report.md에서 이 이름을 설명하는 부분의 직접 인용/발췌 — 코드 블록 포함 가능>
```

## 주의

- report.md의 "핵심 로직 설명"에 없는 이름은 페이지를 만들지 않는다(지어내지 않는다 원칙 — 코드 전체 커버리지가 목적이 아니라 "이미 문서화된 것을 찾아가는" 목적이다).
- **"설명된 버전"은 항상 한 단계 뒤처진다 — 버그가 아니라 구조적 특성이다.** 위키는 자신이 포함될 바로 그 버전이 등록되기 **전에** 만들어지므로, 생성 시점엔 그 버전 번호가 아직 존재하지 않는다. 각 행은 **이미 등록된 버전 중 가장 높은 것**까지만 가리킬 수 있다(CLAUDE.md §6). 이 범위를 넓히려 하지 않는다.
- `README.md`/`docs/report.md`/`history.json`/코드를 고치지 않는다. `wiki/` 아래 파일만 쓴다.
- `register-version`으로 새 버전을 등록하기 **직전**에 호출된다(등록 스킬 절차에 명시돼 있다) — `wiki/`가 그 버전의 스냅샷에 함께 얼어붙기 때문이다. 등록 후에 호출하면 그 시점 스냅샷에는 포함되지 않는다.
- 하위 서브에이전트 호출이 이 환경에서 동작하지 않으면(도구 미인식 등) 조용히 다른 방식으로 대체하지 말고, 호출한 사람에게 바로 보고한다.
